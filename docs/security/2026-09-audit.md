# Security audit — September 2026

This records a full security review of saintTorrent. It also records the fixes on branch `claude/torrent-security-scanning-4ew4xu`, the vulnerabilities from other clients that were checked against this codebase, and what is still open.

- **Starting point:** `main` at `2d48d5c`.
- **Branch:** about 200 commits.
- **Research:** malware scanning was researched separately; see [`docs/design/malware-scanning.md`](../design/malware-scanning.md).

Every fix respects the project's core tenet. None adds synchronous disk I/O, serialization or lock contention to the piece, block or peer-loop hot paths, and none adds a cap that throttles honest swarms. Several fixes remove work from hot paths:

- block I/O does a binary search instead of a linear walk over files;
- a seed's `have_all` costs O(1) instead of O(pieces);
- repeated `PORT` and `Interested` messages are no-ops;
- per-peer goroutine fan-out was replaced by a coalesced have-queue.

## How the audit was done

1. **Internal audit.**
   - One auditor per attack surface: bencode/metainfo, filesystem, peer wire, extension protocol, MSE, DHT, trackers, uTP, webseeds/NAT, local surfaces (HTTP API, TUI, launcher, logging), engine resources, and dependencies/CI.
   - Each finding was then checked by two independent verifiers. The first tried to refute it, with a reproduction where possible. The second traced reachability from real attacker input in the default configuration.
   - A completeness critic twice looked for uncovered areas, which added eight more auditors: lifecycle races, partial-piece memory, Windows path handling, uTP blind sessions, file-count scaling, BEP 27 transitions, crash blast radius, and a prior-art crosswalk.
2. **Other clients.**
   - Seven researchers each mined one family of clients: CVEs, advisories, changelogs, and security-motivated commits in local clones of 18 upstream repositories.
   - Each upstream issue was mapped to saintTorrent's code as vulnerable, partly vulnerable, defended, or feature absent.
   - Every claimed hit was then verified adversarially.
3. **Implementation.**
   - Fixes landed in chains that owned disjoint files, each in its own worktree, and every chain ended with an adversarial review-and-fix pass.
   - A residual round then re-checked all 198 open items against the merged code and fixed the remainder.
4. **Final review** of the merged branch, as described in the summary table.

## What changed

### Crashes and hangs a remote party could cause

- **Metainfo limits.** Metainfo is now bounded by limits taken from libtorrent: piece length ≤ 256 MiB, total size and each file ≤ 2^48, piece count ≤ 2^22, path depth ≤ 128, `.torrent` files ≤ 100 MiB, and a bencode token budget of 3 M. Piece-count math uses int64 everywhere, so 32-bit builds agree with 64-bit ones. These limits close several ways a torrent or magnet could make the process abort on an allocation.
- **Strict info dict.** The `info` dict is decoded strictly: a duplicate key is rejected, and the fields are decoded from exactly the bytes that are hashed. The info-hash therefore always commits to the content.
- **Storage failures are errors, not crashes.** A failure to create storage for a magnet's metadata used to hand back a typed-nil storage that crashed later. It now yields an error the user can see, and the storage factory runs outside the session lock.
- **mmap faults.** A page fault in the mmap backend now becomes an error instead of a fatal SIGBUS.
- **Write deadlines.** Every peer socket has a write deadline (90 s). The peer loop sends keep-alives, and its read deadline (150 s) now matches BEP 3 practice, so quiet honest peers are no longer dropped after 30 s. Per-peer, per-event goroutines were replaced by a have-queue drained by the peer loop.
- **Cheaper availability messages.** A connection accepts only one `bitfield`/`have_all`/`have_none`. Seeds are counted in O(1). Size limits are checked before any extension message is decoded.
- **ut_metadata:**
  - requests go out in a single locked pass, which closes a remote crash;
  - blocks are accepted only from the peer they were requested from;
  - a peer that poisons a round is banned;
  - rejected or unanswered blocks are asked for again;
  - serving is metered and charged to the upload limiter;
  - private torrents never serve it.
- **UPnP and NAT-PMP.** They now run on an in-repo client with bounded response bodies, timeouts and no redirects, so a rogue LAN device can no longer hang shutdown or grow the heap.
- **Crash resilience.** Session goroutines record any panic (info-hash plus stack) and then end the process. On the next start, the implicated torrent is restored paused and quarantined. After two unexplained crashes in a row, every torrent starts paused. `--start-paused` gives the same effect by hand, and SIGHUP now shuts down cleanly.

### Using the client against third parties (SSRF, reflection, DDoS)

- **`pkg/netpolicy`.** This package classifies addresses. An endpoint may be no more local than whoever supplied it: a public tracker, DHT node or PEX sender cannot aim us at loopback, LAN or link-local services, and multicast, broadcast and other unusable addresses are always refused. Trackers named by hostname may still list LAN peers, as in Transmission.
- **Tracker and webseed HTTP.** One hardened HTTP client serves trackers and webseeds. It checks the destination scope of the address actually dialed, follows at most 3 redirects, never downgrades HTTPS to HTTP, and caps headers at 64 KiB. A loopback tracker's path must start with `/announce`, which is libtorrent's `ssrf_mitigation` rule.
- **Tracker lists.** Lists are deduplicated and capped at 200. Announces run with bounded concurrency, and each tracker has its own schedule and backoff. `min interval` is honoured, and intervals are clamped without overflow.
- **Webseeds.** They are deduplicated and bounded by a piece-buffer budget; see the final review's throughput fix. Permanent failures are retired, `Retry-After` is honoured, and credentials never appear in errors or in `/stats`.
- **uTP handshake.** An inbound connection stays half-open until the peer acknowledges our SYN-ACK, which gives return routability and closes the WOOT'15 DRDoS amplification. RESET and FIN are validated, the reorder distance is capped, and unsolicited RESETs are rate-limited. Sequence numbering now matches libutp; before this, handshakes with libutp peers failed.
- **MSE.** The receiver waits for the initiator's key before sending its own, and the handshake flights are coalesced so they no longer carry a fixed-length fingerprint. The key lookup is O(1).
- **DHT.**
  - query rate limits per source IP (libtorrent's dos_blocker);
  - diversity limits: one contact per /24 in each routing bucket and one candidate per /24 in each lookup, like libtorrent's restrict_routing_ips and restrict_search_ips;
  - lookups ordered by XOR distance;
  - nodes inserted under the ID they themselves reported;
  - `values` filtered through netpolicy and capped;
  - bounded announce storage;
  - a lookup scheduler that spreads out the startup burst;
  - a fresh node ID each run;
  - `.dht_nodes` written atomically with mode 0600.
- **PEX.** Receive rate limited, at most 50 added peers per message, a per-IP cap, and nothing advertised before the private flag is known.

### Files on disk

- **Name sanitizing.** Names are cleaned on every platform: control characters and invalid UTF-8 become `_`, bidi and zero-width characters are removed (closing extension spoofing such as U+202E), and each component is at most 255 bytes. Windows device names and reserved characters are mapped.
- **Duplicates and collisions.** Duplicate detection uses NFC plus full case folding. A file path that is also a directory is refused. Torrents that alias one file through a case, normalization or 8.3 variant are refused. Cross-torrent collisions are refused unless the lengths match, which keeps cross-seeding working.
- **Existing downloads keep working.** Files a previous version saved under the old name are renamed in place rather than downloaded again (see the final review).
- **Pre-existing files.** They are never shrunk when a torrent is added.
- **"Delete torrent and files".** It deletes through an anchored `os.Root`, refuses symlinks and Windows junctions, skips files another torrent still uses, and blocks re-adding the same torrent while a removal is still running.
- **Permissions.** State files are 0600 in 0700 directories. The debug log refuses to follow symlinks and refuses hard links or files owned by another user.

### Local surfaces

- **HTTP stats API.**
  - binds to loopback unless `--http-allow-remote` is given;
  - checks the `Host` header (421 otherwise), which closes DNS rebinding, and refuses cross-site requests;
  - caps connections;
  - caches `/stats` for 500 ms.
- **TUI.** It bounds untrusted text and shows hidden format characters as a visible placeholder. The file explorer draws only visible rows. Headless and forwarder output escapes control characters, and the standard library logger is filtered.
- **macOS launcher and CLI.** Only `magnet:?` URLs are accepted; a crafted `magnet:` URL can no longer be turned into a file path.
- **Reveal in file manager.** On Windows the Explorer command line is quoted; macOS uses `/usr/bin/open` by absolute path.

### Toolchain, dependencies and CI

- **Toolchain.** `go 1.26.8` is the floor, and `GOTOOLCHAIN=auto` fetches it. `x/net` moved from v0.10.0 to v0.59.0, and x/sys, x/text, goupnp, go-ssdp and go-netroute were bumped. `go-nat` was replaced.
- **CI.**
  - every action is pinned to a commit SHA;
  - checkout credentials are not persisted;
  - a govulncheck job runs, weekly as well;
  - Dependabot covers gomod and Actions;
  - golangci-lint v2.14;
  - a build-only job for BSD, illumos and Solaris.

## Behaviour changes you may notice

- **Go 1.26.8 or newer is required.** Go installs fetch it automatically unless `GOTOOLCHAIN=local` is set.
- **`--http-addr` binds to loopback only.** A bind to `:PORT` or `0.0.0.0:PORT` needs `--http-allow-remote`. Requests whose `Host` is neither an IP literal, `localhost`, nor the configured host get `421`.
- **Loopback tracker paths.** A tracker URL on a loopback address must have a path starting with `/announce`.
- **Stricter `.torrent` files.** A file with a duplicate key inside `info`, or beyond the size limits above, is refused with an error. A cached torrent that no longer loads is listed as a restore failure; it is not silently dropped.
- **Peer behaviour:**
  - at most 4 connections per remote IP per torrent (loopback exempt);
  - a peer that sends 2 bad pieces is banned for an hour;
  - idle connections where neither side is interested close after 10 minutes;
  - outbound dials prefer TCP.
- **uTP.** While a TCP listener is up, inbound uTP from other clients is refused, so they reconnect over TCP (see the backlog for why). A new saintTorrent cannot use uTP with an old saintTorrent, because sequence numbering changed; those pairs use TCP.
- **Crashes.** After a crash the implicated torrent comes back paused and quarantined. After two unexplained crashes every torrent starts paused. Details are in the README under "State, crashes and recovery".
- **Debug log.** The log refuses symlinks, hard links and files owned by other users. The README no longer suggests a `/tmp` path.

## Known gaps (backlog)

These are deliberately not fixed on this branch: each is a large redesign, needs an owner decision, or would risk throughput or interop.

**Throughput and transport:**
- **Pipelined uTP sender.** `utp.Conn.Write` is stop-and-wait, about one block per RTT. Inbound uTP is therefore refused while TCP is available, and outbound dials prefer TCP. A windowed sender with LEDBAT-style congestion control, fast retransmit and SACK would let uTP carry real traffic. This is the top follow-up.
- **uTP half-open table flooding.** Spoofed SYNs can still flood the half-open table and deny inbound uTP only. Fixing that needs stateless SYN cookies.
- **Global held-bytes budget.** The per-connection cap on partial-piece memory is in place. A manager-wide budget needs sizing benchmarks so it cannot throttle fast disks.

**Protocol hardening:**
- BEP 42 secure DHT node IDs, and preferring verified node IDs. The /24 diversity limits already cover the practical Sybil risk.
- BEP 47 pad files. Hybrid v1/v2 torrents that repeat a pad size are refused, and pad files are downloaded as ordinary files.
- A global outbound DHT packet budget. The lookup scheduler already bounds outbound query volume.
- Private torrents announce to every tracker in their own list in parallel. BEP 27 prefers failover, but nothing leaks.

**Storage at scale:**
- An mmap mapping budget and lazy file creation for torrents with very many files. See the final-review fd-budget item for the descriptor side.
- The resume hint rebuilds the file table under a lock; this matters only for very many-file torrents.
- "Delete with files" still removes a pre-existing file that a torrent adopted. Fixing it needs a persisted per-file ownership record.

**Needs an owner decision:**
- macOS quarantine and Windows Mark-of-the-Web on new files; see the malware-scanning design.
- Excluded file-name globs.
- Refusing privileged ports for peers from DHT or PEX. The current behaviour matches libtorrent's default.
- Token auth for `--http-allow-remote`.
- An opt-in for LAN trackers named by literal IP with arbitrary paths.
- An anonymous mode with per-connection peer IDs.
- Bind-interface or proxy support.

**Documented limitations:**
- v1 torrents rely on SHA-1, so an author could craft colliding pieces. The real fix is BEP 52 (v2 hashes).
- DHT lookups reveal the info-hashes being looked up.
- The macOS launcher's Swift change has not been compiled in CI.
- Windows IPC ACLs apply only when `SAINTTORRENT_IPC_DIR` is overridden.

## Keeping it patched

The concern that started this audit was the lack of security patches for a home-grown client. These safeguards now run continuously:

- **Toolchain floor.** `go.mod` pins the patched Go toolchain. Raise it when a Go security release comes out; govulncheck will flag when one is needed.
- **govulncheck in CI.** It runs on every PR and push and every Monday, and fails when a vulnerable standard-library or module symbol is reachable.
- **Dependabot.** It opens weekly PRs for Go modules and GitHub Actions.
- **Upstream watch.** The table above lists the upstream projects whose security fixes map onto saintTorrent's design. Their changelogs are worth checking when they announce security releases:
  - libtorrent-rasterbar `ChangeLog`;
  - Transmission `news/`;
  - anacrolix/torrent and anacrolix/dht commits;
  - libutp.
